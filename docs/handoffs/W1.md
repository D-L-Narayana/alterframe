## How it was tested

1. Test-first: store / persistence / shortcuts / format tests were written before the modules (initial run: 4 failing files), then implemented to green.
2. Component regressions use `react-dom/server` `renderToStaticMarkup` (no new deps) to assert roles/aria/labels for every primitive and screen. Note: SSR reads zustand's *initial* snapshot, so state-dependent branches are covered via the extracted `RecordingIndicator` / `FpsBadge` components.
3. Browser verification (local Playwright Chromium with fake camera flags against `vite --port 6211`, screenshots kept privately outside the repository): onboarding → camera → stage canvas 1280×800 with the W2 runtime running; `2`/`B`/`F` keys update persona/base/fps badge; `?` opens Help (focus moves to Close), Esc closes; Settings sheet keeps Tab focus inside for 14 presses and restores focus to the Settings button on Esc; `R` starts recording (red dot + 00:02 + toast), `R` again downloads `alterframe-20261002-153854.mp4`; `S` downloads a `.png`; `D` toggles director; 390 px viewport shows the compact bar and the "More controls" bottom sheet. No page errors (only MediaPipe's XNNPACK info lines, which Chrome logs at error level).

## Project overrides applied (differ from ten-worker-contracts.md §W1)

- **Settings are memory-only.** No `localStorage`/`sessionStorage` is touched (preview-sandbox compatibility). The store still serialises to the versioned `alterframe.settings.v1` envelope through a `SettingsStorage` adapter, and the round-trip is unit-tested with `createMemoryStorage()`. To enable real persistence later, pass a Web Storage adapter to `createAppStore({ storage })` — a 6-line change in `src/state/store.ts`, no other code moves.
- **Production controls use the real `RuntimeHandle` via a React ref** (`handleRef` from `useRuntime` → `useActions` → bar/sheet/shortcuts). `window.__alterframe` is never read by W1 code; it remains a W2 dev/e2e-only bridge.
- **Font:** `@fontsource/inter` is **not** installed (W10 is the sole package editor). `--af-font` falls back to `Inter, ui-sans-serif, system-ui, …`. Request below.

## Integration notes for the lead / other workers

- `useRuntime` calls `source.start()` itself before `startRuntime` so the UI can show precise denied/unavailable/error states; W2's `ensureStarted` only starts idle sources and camera `start()` is idempotent, so there is no double `getUserMedia`. The runtime's own `syncSourceSession` and W1 write the same fields — no conflict observed.
- The "Loading tracking models…" bar is shown while `sourceStatus === 'ready' && !trackerReady`; W2's runtime sets `trackerReady` from `tracker.ready` (verified in `src/runtime/index.ts`). A model-download progress value is not in `SessionSlice`, so the bar is indeterminate.
- `recorderState`/`recorderElapsedMs` are written by W1 actions; W2 also mirrors `recorder.state` each frame — identical values, idempotent.
- Capture aspect lives in `useUiStore.captureAspect` (not in the shared `AppState`); W9's recorder receives it through `recorder.start({ aspect })` / `handle.snapshot(aspect)`.
- The stage canvas has `role="img"` + descriptive `aria-label`; the controls `<nav aria-label="Stage controls">` follows a skip link.
- `tests/unit/app/components.test.tsx` mocks `@/app/runtimeBridge`, so it never touches WebGL/MediaPipe.

- No axe run yet (W10/lead). Manual review: every control has a name, dialogs are modal with trap/restore, 44 px targets, visible focus ring, `prefers-reduced-motion` honoured, live regions present.
