### Behaviour summary

**Quad (per lead correction, reference-analysis §4b.1):** emitted whenever two hands pass `minHandScore` with finite tips/palm — **no area or gesture gating**. Zero-area slits (closed fists) return a quad with `area = 0`, `thickness ≈ 0`, finite centroid. Corners are copied (never aliased to tracker objects).

- `selectHands`: drops hands with non-finite score/tips/palm or coordinates beyond ±4 (tracker garbage); keeps the two highest scores; `[left, right]` by `palmCenter.x`, ties → `indexTip.x` → `side` label.
- **convex**: per hand `top` = smaller y (tie → index), quad `[L.top, R.top, R.bottom, L.bottom]`; if top edge ∩ bottom edge → swap R corners; if the two vertical edges still cross (tips straddle) → the remaining simple cyclic order `[L.top, R.top, L.bottom, R.bottom]`. Property-tested over 2 000 random layouts: never self-intersecting, always the same four tips, each hand keeps two corners. Hysteresis: when a hand's two tips are within 0.01 in y and `prev` (visible, convex) is supplied, the previous top/bottom assignment is kept (no flicker at equal heights).
- **faithful**: fixed `[L.index, R.index, R.thumb, L.thumb]` → reproduces the bow-tie (§4b.4).
- `thickness` = mean of the two per-hand index–thumb distances (ordering-independent); `area` = unsigned shoelace; `centroid` = vertex mean (finite even at area 0; see assumptions).
- Intersection test is a proper-crossing test: shared endpoints, touching and collinear/zero-length segments are not crossings.

**Interaction state machine:** `update(frame|null, t, scene, settings)` →
- hold/fade: after the pair is lost, opacity = 1 for `holdMs` (inclusive), then linear to 0 over `fadeMs`; at `holdMs + fadeMs` the quad becomes `null`. Hands returning mid-fade → opacity 1 immediately. `fadeMs = 0` safe. Clock going backwards / NaN `t` → treated as no time elapsed (never NaN opacity). Held quad keeps the last live corners/area/thickness.
- events: `window-open` / `window-close` **only** on the visibility edge (quad non-null ↔ null), prepended before gesture events in the same frame.
- `debug`: `{ armed, togetherMs, handsUsed }` (`handsUsed` = hands passing score + finite tips, 0–N).
- `reset()` clears quad, edge state, gesture and spring.

**Gesture (optional design interpretation, not an observed mechanic — §4b.2):** together ⇔ palms within `togetherDistance` AND (no quad OR `area < openArea/2`) for ≥ `togetherArmMs` → `hands-together-armed` (once per arming). Armed + quad with `area > openArea` → `cycle-persona { next: PERSONA_ORDER[(i+1)%3] }`, disarm. Debounce 1 500 ms: a second attempt inside the window is **dropped** (not deferred) and disarms. Armed state is dropped if no usable pair is present for > 2 000 ms. `gestureCycleEnabled=false` → never arms, no gesture events. The persona used for `next` is `scene.persona` passed by the runtime (so Director/UI changes are respected).

**Director:** `start(t)` → running; `update(t)` returns a fresh `SceneState` for the step containing `(t − startT) mod total` (half-open intervals, boundary → following step); loops; `stop()` → `update` returns `null`; steps with non-positive durations are skipped; empty sequence → running but `null`. Non-finite / pre-start `t` clamps to step 0. Defensive copy of the sequence. Verified: t = 0, 13.9, 15.5, 20.5, 22.3 s → steps 0..4; 23.7 s → step 0.

**Spring (off by default):** closed-form critically damped integration (`x(t) = (A + Bt)e^{−ωt}`), stable for any dt (hidden tab → lands on target). `stiffness` is "fraction of the gap closed per 60 Hz frame from rest" (0.35 per contract) and converted to ω, so lag is frame-rate independent. First sample snaps. Enable with `createInteraction({ cornerSpring: { stiffness: 0.35 } })`.

**debugDraw:** pixel space from `size`; hand skeleton (blue = screen-left, pink = screen-right), small dots for landmarks, yellow circles at index/thumb tips (the four corners), face anchors, quad outline + two text lines (quad stats, gesture state) when `extras` given. Skips any non-finite point; zero-size canvas safe. Accepts `CanvasRenderingContext2D` or `OffscreenCanvasRenderingContext2D` (structural `DebugCanvas2D`).

## Assumptions

1. `centroid` is the vertex mean, not the area-weighted polygon centroid (undefined at area 0, which is a legitimate slit state). Difference is negligible for near-parallelograms.
2. Convex mode guarantees a **simple** (non-self-intersecting) quad, not strict convexity: if one tip lies inside the triangle of the other three, the quad is a "dart". W4 triangulates `(0,1,2),(0,2,3)`; for a dart whose reflex vertex is at index 1 or 3 that diagonal is exterior and the mask under-covers slightly. Rare with real hands (tips of one hand would have to sit inside the other hand's span).
3. Gesture debounce drops (does not queue) a cycle; disarm after 2 s of no hands. Both are W7 choices beyond the contract text.
4. `computeWindowQuad`'s `t` parameter is unused by the pure geometry (kept for the contract signature); `prev` is used only for top/bottom hysteresis.
5. Landmarks beyond ±4 normalized units are treated as invalid; slightly off-frame tips (−0.2…1.2) are accepted as MediaPipe produces them.
6. Director returns `hudTint` derived from base per contract; per lead-checklist B8, W2 should route it through the store's `setScene` so `hudTintAuto` overrides apply.
7. Port 6217 used for the harness as assigned in the lead mail (lead-checklist lists 5179 for W7; mail supersedes).

## Known gaps

- No e2e here (W10 owns); the harness is synthetic, so real-tracker jitter/hysteresis tuning (`TOP_BOTTOM_HYSTERESIS = 0.01`) is a guess pending camera testing.
- The spring is opt-in and not surfaced in `InteractionSettings`; the runtime would need to pass `createInteraction({ cornerSpring })` to enable it.
- `handsUsed` counts qualifying hands even when >2 (only two are used); documented, not a bug.
