### Behaviour (contract W8 + lead errata)
- `quad?.visible` → `corner` callout at `corners[0]`, code `NN10100`, bracket. Face present → `eye-left` at `face.leftEye` (`NN10301`, leader → corner anchor). `eye-right` at `face.rightEye` (`NN10502`, leader → eye-left) only when `quad.area > 0.06`. Leader chain never dangles: if `leftEye` is non-finite, eye-right chains from the corner.
- Mouth box when `face.mouthOpen > 0.35`: `w = 1.6 × |MOUTH_LEFT−MOUTH_RIGHT|`, `h = 1.6 × max(lip gap, 0.25 w)`, centred on the mean of the four mouth landmarks. Carried in `model.boxes` (see contract request 1). `callout.box` from the contract is also drawn if present.
- Thin slits (errata §4b.1/5): callouts do not depend on thickness — a 2–3 px slit still gets corner + eye-left; eye-right only once the window is large. Test: `model.test.ts › thin slits`.
- `opacity = clamp(quad.opacity)`; all callouts/boxes drawn with that `globalAlpha`. Record dot and fps badge ignore it.
- Draw: `font: 300 ${round(0.0185·h)}px Inter, "Inter Variable", system-ui, …, sans-serif` (min 11 px), manual tracking 0.04 em per glyph, fill `#f5f5f7` / `#ff2b2b`, 1 px leaders + 6×6 px L bracket with `rgba(0,0,0,.35)` 2 px shadow, baseline 6 px above anchor, right-aligned when `anchor.x > 0.7`, horizontal clamping to the canvas, flip below the anchor (clearing the bracket arm) when there is no room above, bracket anchor clamped into the canvas for off-screen anchors.
- Record dot: 10 px red, top-right, 1 Hz 50 % duty from `model.t`; solid under reduced motion. fps badge top-left (`"60 fps"`) when `extras.showFps && fps !== null`.
- Dirty flag: `draw` computes a structural key (callouts, boxes, size, tint, opacity, fps, blink phase); identical key → no draw, `canvas.__dirty = false`; otherwise draw and `__dirty = true`. Resize and `setOptions` force a redraw. Debug mode disables dedupe.
- Coordinate space: the HUD is agnostic — it draws into whatever `resize(size)` says. Per the lead's agreement, W2/W4 should size it to the **video frame** (`sourceWidth × sourceHeight`); W4 applies the single cover-fit. Font size is therefore 1.85 % of the *video* height (13 px at 720p, 20 px at 1080p), scaled by the cover-fit on screen — this matches the reference, which was itself 1080p.

## Wiring notes for W2 (runtime)

```ts
import { createHud } from '@/hud';
import { drawLandmarks } from '@/interaction/debugDraw';   // W7 — signature verified compatible
const hud = createHud({ debugDraw: drawLandmarks, reducedMotion: store.getState().reducedMotion });
hud.resize({ width: sourceWidth, height: sourceHeight });   // video-frame space, on source change
// per frame
const s = store.getState();
hud.setOptions({ reducedMotion: s.reducedMotion, debugLandmarks: s.debugLandmarks });  // cheap; only invalidates when something changes
const model = hud.buildModel(frame, quad, s.scene, t, { recording: recorder.state === 'recording', fps: perf.fps(), showFps: s.showFps });
hud.draw(s.hudEnabled ? model : { ...model, callouts: [], boxes: [], opacity: 0 });  // or skip composite when HUD disabled
inputs.hudOverlay = hud.canvas;
```
`setOptions` resets the dedupe key, so call it only when values actually change if you want the dirty-flag savings (or compare before calling).

## Contract-change requests (for the lead; nothing edited in `src/types`)

1. `src/types/hud.ts` — add `'mouth'` to `HudCallout['id']` (or add `boxes?: { center: Vec2; w: number; h: number }[]` to `HudModel`). Reason: the contract's mouth box is "centred at anchor", but no callout id may be anchored at the mouth. W8 currently returns it in `HudModelExt.boxes` (a superset of `HudModel`), which W2 passes through untouched; W4 only sees the canvas, so nothing breaks either way.
2. `Hud.buildModel` extras lack `reducedMotion`/`debugLandmarks`; W8 exposes `createHud({ reducedMotion, debugLandmarks, debugDraw })` + `setOptions()` instead. Optionally formalise `HudOptions` in the contract. Default for `reducedMotion` is `prefers-reduced-motion`.
3. (Informational) `HudCallout.code` suffixes for `hand-left`/`hand-right` are defined as `10704`/`10905` in `CODE_SUFFIX` but no callouts use them yet.

## Known gaps / honest notes

- The mouth box is axis-aligned (contract `{w,h}`); it does not rotate with head roll. Visible in harness case B (rolled head).
- White labels over the paper-white portrait window are low-contrast by design (faithful to the reference); the 2 px `.35` shadow keeps them legible but a lead may prefer `.5` on light backdrops — one constant (`SHADOW_COLOR`).
- No real-camera verification (sandbox has no camera); all pixels come from synthetic models.
- Glyph widths are measured per glyph each draw (7 glyphs × ≤ 3 labels); negligible, and dedupe skips most frames.
- The harness dev server started with `start_server` on 127.0.0.1:6218 may still be running (log: `app/.hud-harness-6218.log`); kill it if the port is needed.
