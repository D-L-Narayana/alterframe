### Recorder behaviour (W2 integration notes)

* `start({ aspect, fps = 30, videoBitsPerSecond = 12_000_000, mimeCandidates? })`
  * `source` aspect: `stage.captureStream(fps)` directly, no extra canvas.
  * other aspects: an intermediate `dw×dh` canvas is created; the stage is centre-cropped into it immediately (first frame not blank) and on every `requestAnimationFrame` while recording; the crop plan is recomputed each frame so a stage resize mid-recording is followed, output size stays fixed.
  * `MediaRecorder.start(1000)` timeslice → chunks arrive every second (bounded chunk size; memory still grows with duration, see gaps).
* `stop()` → `Promise<{ blob, mime, durationMs }>`; `blob.type` is the bare container (`video/mp4` / `video/webm`); use `extensionForMime(mime)` for the filename. A second `stop()` during `finalizing` returns the same promise. A 5 s safety timeout resolves with whatever chunks exist if the `stop` event never fires.
* `state`: `idle → recording → finalizing → idle`; `elapsedMs` is live while recording, frozen while finalizing, 0 when idle.
* `RecorderDeps.onStateChange(state, elapsedMs)` is the cheap hook for mirroring into `session.recorderState` (otherwise poll `state`/`elapsedMs` per frame).
* Cleanup on stop and on every error path: rAF cancelled, all stream tracks stopped, crop canvas zero-sized, chunks dropped.
* Errors are rejected promises with readable messages:
  `Recorder is already recording.` · `Recorder is still finalizing the previous recording.` · `Not recording.` ·
  `MediaRecorder is not supported in this browser; recording is unavailable.` · `canvas.captureStream is not supported…` ·
  `No supported video format for recording (tried …).` · `Cannot crop an empty canvas (0×0)…` ·
  `Could not start recording: <browser message>` (with `cause`) · `Recording failed: <MediaRecorder error>` (an error event mid-recording resets to idle; the next `stop()` rejects with it once) · `Recording produced no data (…)`.
* `recorder.snapshot(aspect)` delegates to `snapshot(getCanvas(), aspect)`. Snapshot requires W4's `preserveDrawingBuffer: true` (contracted).

### Perf / adaptive behaviour

* `fps()` = EMA of 1000/dt between `sample()` calls with time-based alpha `1 − exp(−dt/500)`; 0 until two frames; a gap > 2 s (tab hidden) re-seeds instead of collapsing to ~0.
* `recent(ms)` oldest-first; buffer pruned to 5 s.
* Policy (`evaluate(samples, current)`): time comes from the samples' `t`, not a clock (deterministic). Samples with `fps === 0` (warm-up) and samples taken at/before the last change are ignored.
  * step **down** when median fps over the last 2 s < 22 and ≥ 2 s of history exist: `renderScale −0.15 → … → 0.5`, then `segmentationStride 1→2→3`; `null` at the floor.
  * step **up** when **every** sample over the last 5 s is > 40 and ≥ 5 s have passed since the last change: stride `3→2→1` first, then `renderScale +0.15 → 1`.
  * 3 s cooldown between any two changes. `maxDpr` never touched. Works from `current` so user changes in Settings are respected.
  * Typical real trace (harness, 60 ms busy-wait per frame): 1 → 0.85 at ~2 s, → 0.7 at ~5 s; after releasing load, restoration begins ~6–8 s later (EMA recovery samples must leave the 5 s window), then one rung per 3 s.

## Known gaps / notes

* Recorded duration vs decoded duration: MP4 output decoded 0.1–0.3 s shorter than `durationMs` (encoder start-up drops the first frames). `durationMs` is wall time between start and stop.
* Non-`source` aspects upscale small stages to the fixed 1080-based sizes per contract (a 640×360 stage still yields 1080×1920). If undesired, cap `OUTPUT_SIZES` later (one-line change in `crop.ts`).
* Chunks are held in memory for the whole recording (~90 MB/min at 12 Mbps). Fine for reel-length clips; no streaming to disk (no persistent storage by design).
* `captureStream` stops delivering frames while the tab is hidden; recording a backgrounded tab yields frozen/short video (browser behaviour, not handled).
* `defaultAdaptivePolicy` is a shared instance: its cooldown clock is global to the page. W2 may prefer `createAdaptivePolicy()` per runtime.
* The recorder is not wired to `visibilitychange`/`beforeunload`; W2/W1 should call `stop()` when tearing down.
* Harness `main.tsx` is plain DOM TypeScript (no React) to stay dependency-free; `index.html` is the entry.
