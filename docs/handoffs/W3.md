## 2. Exported API (`@/tracking`)

```ts
createTracker(opts?: AlterFrameTrackerOptions, onProgress?: (p01: number) => void): AlterFrameTracker
// AlterFrameTracker extends Tracker (contract) with getInfo(): TrackerInfo

interface AlterFrameTrackerOptions extends TrackerOptions {   // contract options unchanged
  segmentationDelegate?: 'GPU' | 'CPU' | 'inherit';            // default 'CPU' (see §3.3)
  maskFlipY?: 'auto' | 'always' | 'never';                     // default 'auto' (= no flip, see §3.3)
  smoothingResetMs?: number;                                   // default 500
}
interface TrackerInfo {
  delegates: { hands: 'GPU'|'CPU'|null; face: …; segmentation: … };  // actual after fallback
  warnings: string[];            // e.g. "[tracking] face: GPU delegate failed (...); falling back to CPU"
  pending: Promise<void>;        // resolves when a setOptions re-configuration has been applied
  segmentationLabels: string[];  // ['selfie'] for the shipped model
  segmentationChannel: number;   // confidence-mask channel read (0)
  lastMaskFromGpu: boolean; lastMaskFlippedY: boolean; lastMaskSize: {width,height} | null;
}
```

Defaults: `modelBaseUrl '/models'`, `wasmBaseUrl '/wasm'`, `delegate 'GPU'`, `numHands 2`, face + segmentation on, `segmentationStride 1`, `mirrored true`, smoothing `{minCutoff 1, beta 0.02, dCutoff 1}`.

Behaviour summary
- **Coordinates**: normalized intrinsic **video frame** [0,1], top-left origin, mirrored **exactly once** here (`x → 1-x` on every landmark, mask columns reversed). No knowledge of the CSS canvas / cover-fit. `sourceWidth/Height` = `video.videoWidth/Height`.
- **Hands**: `numHands` from options, VIDEO mode, min confidences 0.5. Per-hand One-Euro slots are matched frame-to-frame by palm-centre proximity (`matchHands`) so detector reordering does not reset smoothing; a slot resets after > 500 ms unseen. `score` = handedness category score. Output sorted by `palmCenter.x`; `side` = `'left'` for the smaller x (two hands) or by screen half (one hand). `size` = wrist→middle-MCP distance in frame-height units (aspect-corrected).
- **Face**: 1 face, blendshapes + transformation matrix on. `leftEye/rightEye` are **viewer** left/right (smaller x = left) with `eyeOpenLeft/Right` swapped consistently (blendshapes are anatomical). `roll = atan2(dy, dx·aspect)` of the left→right eye vector (positive = clockwise on screen; sign flips under mirroring). `faceBox` = landmark bounds. `mouthOpen = jawOpen`, `smile = mean(mouthSmileL/R)`, `eyeOpen = 1 - eyeBlink`, each with landmark-distance fallbacks. `transform` = MediaPipe `Matrix.data` as Float32Array (column-major, **camera space, not mirrored** — consumers should use the display-space landmarks).
- **Segmentation**: `outputConfidenceMasks: true`, channel for label `selfie|person|foreground` (index 0 for the shipped single-label model). Runs on frame 1 and then every `segmentationStride` frames (the previous `SegmentationResult` object is reused in between; a **new object identity** signals new data — W4 can use that to skip re-uploads). Mask resampled from native (= input) resolution to **256×256** into one reusable `Float32Array`; `texture: null` always (the MediaPipe texture lives in MediaPipe's own GL context and is unusable by W4).
- **Frame caching**: `update()` returns the previous `TrackingFrame` when `video.currentTime` is unchanged or `readyState < 2`; returns an empty frame before `init()`/after `dispose()`. MediaPipe timestamps are forced strictly increasing even if `t` goes backwards.
- **GPU→CPU fallback**: (a) if `canvas.getContext('webgl2')` is null → CPU directly; (b) if `createFromOptions` with GPU throws → retried with CPU for that task only; (c) if `detectForVideo`/`segmentForVideo` throws at runtime on a GPU task → that task is rebuilt on CPU asynchronously (hands/face share `delegate`, so both rebuild); a CPU failure disables the task and records a warning. Nothing is logged to the console; see `getInfo().warnings`.
- **Progress**: 0 → 0.08 after wasm → bytes streamed (weighted by real content-length, hand model dominates) → +0.10 across task construction → exactly 1. Monotonic.
- **setOptions**: `mirrored`/`segmentationStride`/`smoothing` apply immediately (mirror flip also resets smoothing state and drops the stale mask); `delegate`/`numHands`/`enableFace`/`enableSegmentation`/`segmentationDelegate` trigger an async rebuild of the affected tasks from the cached model bytes (no re-download); `getInfo().pending` resolves when done.
- **Resource cleanup**: `segmentForVideo` is used in **callback form** so the `MPMask` is owned and freed by the task when the callback returns (we only copy out of it; no `clone()`). `dispose()` closes all three tasks, clears the model cache and makes `ready=false`; task replacement during reconfiguration closes the old instance.

### 3.3 Decisions worth knowing
- **Segmentation runs on the CPU delegate by default** (`segmentationDelegate: 'CPU'`): the contract needs a CPU `Float32Array`, the model is 256×256, and the GPU path costs a synchronous `readPixels` of a full-input-resolution float texture (1280×720×4 B) per stride frame. Hands/face keep `delegate: 'GPU'`. If the lead prefers the contract's literal "GPU for everything", pass `segmentationDelegate: 'inherit'`.
- **Mask orientation**: verified top-left for both paths (§3.2) — W4 must **not** flip the mask (lead-checklist B2/B3). The mask is already mirrored; W4 flips only the video UV.
- **One-Euro defaults** (`minCutoff 1, beta 0.02`) give ≈160 ms time constant: smooth, but ~5 frames of lag on a step (test documents it). Product criterion A1 asks for ≤ 2 frames of smoothing lag; in normalized units `beta` ≈ 0.3–0.5 would keep rest-jitter suppression while opening the cutoff on fast moves. Left at the contract defaults; W7's corner spring should **not** add more lag on top. Suggest the lead tunes `smoothing` in the store once real-camera testing is possible.
- Smoothing is applied to raw mirrored landmarks **before** derivation, so tips/palm/anchors are consistent with `landmarks[]`.

## 4. Not verified / known gaps
- **Real camera, real GPU, real fps**: not possible in the sandbox. Needs the user's local run of the harness (`npx vite --port 6213`, open `/src/tracking/__harness__/index.html`, "Use camera").
- GPU **init-throw** and **runtime-throw** fallbacks (paths b/c in §2) are covered by mocked tests only; the real-browser fallback test exercised path (a) (no WebGL2).
- Runtime-failure rebuild of hands/face rebuilds both on CPU (shared `delegate`) — chosen for simplicity; a per-task delegate would need a contract change.
- `transform` is not mirrored (camera space). If W6 ever needs it in display space, a mirrored copy (`diag(-1,1,1,1) · M`) can be added as a derived field on request.
- Face smoothing uses the same One-Euro params as hands (478 × 3 filters ≈ 0.1 ms/frame).
- Hand `score` is the handedness classification score (the only per-hand confidence the Tasks API exposes).
- The `tests/unit/tracking` suite runs under W10's `vitest.config.ts` (node env). The tracker tests stub `fetch` and `@mediapipe/tasks-vision`; they do not touch the network.

## 5. Contract-change requests (for the lead; coded against the current contract)
1. *(optional)* `TrackerOptions.segmentationDelegate?: 'GPU'|'CPU'|'inherit'` and `maskFlipY?: 'auto'|'always'|'never'` — currently W3-only extensions on `AlterFrameTrackerOptions`; W2 can pass them today since the factory accepts a superset of `TrackerOptions`.
2. *(optional)* `Tracker.getInfo?(): TrackerInfo` on the contract so W1 can show "GPU/CPU" and fallback warnings in Settings/diagnostics without a cast.
3. *(docs)* `SegmentationResult.texture` should be documented as "always null in the current implementation" (MediaPipe's texture is in a foreign GL context).
4. *(docs)* `TrackingFrame.segmentation` identity: "a new object each time the mask is refreshed; same object between stride frames" — useful for W4's upload skipping.
