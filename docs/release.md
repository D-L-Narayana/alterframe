# Release and repository hygiene

## What ships

The public repository is the contents of `app/` at its root. Planning documents, reference
material and anything quoting third-party creators stay **outside** the app folder and are never
committed. Generated or fetched binaries are gitignored and regenerated by npm lifecycle scripts:

| Path | In Git | Regenerated by |
|---|---|---|
| `public/models/*.task`, `*.tflite` (≈ 11.8 MB) | no | `predev` / `prebuild` → `scripts/fetch-models.mjs` (retries, size checks) |
| `public/wasm/**` (≈ 35 MB) | no | `postinstall` / `predev` / `prebuild` → `scripts/copy-wasm.mjs` |
| `tests/fixtures/hands.y4m` (≈ 125 MB) | no | `npm run fixture` / `pretest:e2e` → `tests/fixtures/make-fixture.mjs` |
| `tests/fixtures/hands.schedule.json` (28 kB) | yes | same generator (checked for drift by a unit test) |
| `dist/`, `test-results/`, `playwright-report/`, `coverage/` | no | builds / test runs |

`scripts/verify-dist.mjs` (postbuild) fails the build if `dist/` lacks models, wasm, hashed
assets, favicon/manifest, or contains inline scripts / CDN references.

## Node version

Vite 8.3 requires Node `^20.19.0 || >=22.12.0`; ESLint 10 requires `^20.19.0 || ^22.13.0 || >=24`.
`package.json#engines` mirrors Vite's range; CI uses Node 22 (satisfies both). Vercel: set the
project Node.js version to **22.x** (Vercel reads `engines` as a hint but the dashboard setting
wins). A plain "Node 20" setting may resolve to 20.x < 20.19 on some platforms and fail.
`tests/unit/infra/ci.test.ts` cross-checks CI's Node version against the *installed* engine ranges.

## Caching policy

* `/assets/*` — content-hashed by Vite → `public, max-age=31536000, immutable`.
* `/models/*`, `/wasm/*` — **not** content-hashed (file names are stable, contents change with
  MediaPipe versions/"latest" models) → `public, max-age=86400, stale-while-revalidate=604800`.
  Marking them immutable would strand users on stale models after an upgrade. To make them
  immutable, version the paths (e.g. `/wasm/1.0.1/`) — a contract change for W3's
  `wasmBaseUrl`/`modelBaseUrl` defaults.
* `/index.html` — `max-age=0, must-revalidate`.

## Hygiene gate

Run before any push: `npm run test:hygiene` (vitest) or `node scripts/hygiene.mjs --git`
(scans `git ls-files`). Scope is the tracked/deployable payload, not `node_modules` or generated
output. Legitimate third-party attribution (Google/MediaPipe copyright, Inter OFL text, source
URLs) is **kept** — the forbidden-string list targets the reel host, franchise/trademark names,
the creator handle and reference-material paths only.

## Steps

1. `npm ci && npm run check && npm run build` — all green, `verify-dist` ok.
2. `npm run fixture && npx playwright test` — e2e green (visual baselines committed).
3. `node scripts/bundle-report.mjs` — JS gzip ≤ 450 kB.
4. `git init` in `app/`, `node scripts/hygiene.mjs --git`, review `git ls-files | xargs du -ch | tail -1`.
5. Push to the public repository (MIT), import in Vercel (framework Vite, Node 22.x, build
   `npm run build`, output `dist`, install `npm ci`).
6. Post-deploy: headers (`curl -I`), model/wasm URLs return 200 with expected sizes, camera prompt
   over HTTPS, 10 s recording downloads, no console CSP violations.
7. Write `docs/verification.md`: what was verified how; what remains user-side (real camera).
