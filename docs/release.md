# Release and repository hygiene

## What ships

The public repository is this tree. Planning material and anything quoting third-party creators stay
**outside** it and are never committed (`docs/handoffs/` keeps the historical 0.1 build notes only).
Generated or fetched binaries are gitignored and regenerated by npm lifecycle scripts:

| Path | In Git | Regenerated by |
|---|---|---|
| `public/models/*.task`, `*.tflite` (≈ 11.8 MB) | no | `predev` / `prebuild` → `scripts/fetch-models.mjs` (retries, size checks) |
| `public/wasm/**` (≈ 35 MB) | no | `postinstall` / `predev` / `prebuild` → `scripts/copy-wasm.mjs` |
| `tests/fixtures/hands.y4m`, `hands-still.y4m` (≈ 135 MB) | no | `npm run fixture` / `pretest:e2e` → `tests/fixtures/make-fixture.mjs` (CI caches them keyed on the generator) |
| `tests/fixtures/hands.schedule.json` (28 kB) | yes | same generator (checked for drift by a unit test) |
| `dist/`, `test-results/`, `playwright-report/`, `coverage/`, `*.log` | no | builds / test runs |

`scripts/verify-dist.mjs` (postbuild) fails the build if `dist/` lacks models, wasm, hashed
assets, favicon/manifest, or contains inline scripts / CDN references / dev-hook strings.

## Node version

Vite 8.3 requires Node `^20.19.0 || >=22.12.0`; ESLint 10 requires `^20.19.0 || ^22.13.0 || >=24`.
`package.json#engines` mirrors Vite's range; CI uses Node **22.23** (satisfies both). Vercel: set the
project Node.js version to **22.x** (Vercel reads `engines` as a hint but the dashboard setting
wins). A plain "Node 20" setting may resolve to 20.x < 20.19 on some platforms and fail.
`tests/unit/infra/ci.test.ts` cross-checks CI's Node version against the *installed* engine ranges.

## Caching policy

* `/assets/*` — content-hashed by Vite → `public, max-age=31536000, immutable`. The tracking
  (MediaPipe) code is a separate hashed chunk loaded on tracker init.
* `/models/*`, `/wasm/*` — **not** content-hashed (file names are stable, contents change with
  MediaPipe versions/"latest" models) → `public, max-age=86400, stale-while-revalidate=604800`.
  Marking them immutable would strand users on stale models after an upgrade. To make them
  immutable, version the paths (e.g. `/wasm/1.0.1/`) — a contract change for the tracker's
  `wasmBaseUrl`/`modelBaseUrl` defaults.
* `/index.html` — `max-age=0, must-revalidate`. Note that with `cleanUrls` the document is served at
  `/` (a request for `/index.html` redirects there), so the platform default for `/` applies — also
  `public, max-age=0, must-revalidate` on Vercel; `scripts/serve-dist.mjs` mirrors both.

## Hygiene gate

Run before any push: `npm run test:hygiene` (vitest) or `node scripts/hygiene.mjs --git`
(scans `git ls-files`). Scope is the tracked/deployable payload, not `node_modules` or generated
output. Rules (0.2 additions in bold): size/media/`.env`, **no `*.log` files**, **no absolute
paths into a home directory**, **no references to retired internal planning documents outside
`docs/handoffs/`**, forbidden strings, raster images, source policy. Legitimate third-party
attribution (Google/MediaPipe copyright, Inter OFL text, source URLs) is **kept** — the
forbidden-string list targets the reel host, franchise/trademark names, the creator handle and
reference-material paths only.

## Steps

1. `npm ci && npm run check && npm run build` — all green, `verify-dist` ok.
2. `node scripts/bundle-report.mjs --strict` — total JS ≤ 450 kB gz, entry chunk ≤ 128 kB gz,
   `entry-chunk MediaPipe check: OK` (v0.2 measured by Vite's build output, decimal kB: entry
   125.1 kB gz, tracking chunk 52.1 kB gz, total 177.2 kB gz).
3. `npm run fixture && npx playwright test` — e2e green (visual baselines committed; only
   environmental skips, each with its reason).
4. `node scripts/with-server.mjs -- npm run test:prod-gate` — the production gate against the built
   `dist` served with the `vercel.json` headers: no dev hooks, no inline scripts, 0 CSP violations,
   headers exact.
5. `node scripts/hygiene.mjs --git` — zero findings. Review `git ls-files` for anything unexpected.
6. Tag `v0.2.0`; push; Vercel builds (framework Vite, Node 22.x, build `npm run build`, output
   `dist`, install `npm ci`).
7. Post-deploy: `curl -I https://<host>/` (CSP exactly as in `vercel.json`, Permissions-Policy, COOP,
   CORP, nosniff, X-Frame-Options), `curl -sI https://<host>/models/hand_landmarker.task` (200,
   content-length 7819105, `stale-while-revalidate`), `curl -sI https://<host>/wasm/vision_wasm_internal.wasm`
   (200, `application/wasm`); then `E2E_PROD_URL=https://<host> npx playwright test tests/e2e/production-gate.spec.ts`.
8. Update `docs/verification.md` with the run snapshot (commit, CI run id, counts, environment
   labels); what remains user-side (real camera) stays listed as such.

Rollback: redeploy the previous Vercel deployment; there are no data migrations (memory-only settings).
